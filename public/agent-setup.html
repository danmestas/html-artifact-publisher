Set up an agent to publish here

Give your agent the publishing skills and CLI once. Afterwards it can publish pages to this instance and revise them, without you copying URLs by hand.

Copy the setup prompt

Paste this into your agent. It names this instance, tells the agent to read /llms.txt first, and asks before installing anything.

The prompt is built from this page's address, so it always points at this instance. If copying is blocked, the text is selected for you to copy with your keyboard.

Download the skills and CLI

The download contains the repository's source. It includes the skills in skills/, the CLI in scripts/publish-html.mjs, and the shared assets in public/ that those scripts import.

Download skills + CLI (.zip) View the source on GitHub

This is a source bundle, not an installer. Unpack it into a tools directory, then point your agent at the skills inside skills/. Node.js 22 or newer is enough to publish; Go, TinyGo and a server deployment are not needed.

Or clone it

Cloning keeps the checkout easy to update later. The CLI and its assets live in that checkout, so keep it — and have the commands you run name it, as explained below.

set -e
checkout="$HOME/tools/html-artifact-publisher"
expected_origin="https://github.com/danmestas/html-artifact-publisher.git"
if [ -e "$checkout" ] || [ -L "$checkout" ]; then
  if [ ! -d "$checkout/.git" ]; then
    echo "Error: $checkout exists but is not a git checkout. Move it aside and rerun; nothing was changed." >&2
    exit 1
  fi
  origin="$(git -C "$checkout" remote get-url origin 2>/dev/null || true)"
  if [ "$origin" != "$expected_origin" ]; then
    echo "Error: $checkout is a git checkout of ${origin:-<no origin>}, not $expected_origin. Move it aside and rerun; nothing was changed." >&2
    exit 1
  fi
  for required in scripts/publish-html.mjs public skills/publish-html-page; do
    if [ ! -e "$checkout/$required" ]; then
      echo "Error: $checkout is missing $required; it is not a usable checkout. Move it aside and rerun; nothing was changed." >&2
      exit 1
    fi
  done
  echo "Using existing checkout at $checkout."
else
  git clone "$expected_origin" "$checkout"
fi
mkdir -p "$HOME/.claude/skills"
for skill in publish-html-page artifact-design artifact-runtime artifact-diagrams artifact-dataviz pikchr; do
  target="$HOME/.claude/skills/$skill"
  if [ -e "$target" ] || [ -L "$target" ]; then
    echo "Skipped $skill: $target already exists; left unchanged."
    continue
  fi
  ln -s "$checkout/skills/$skill" "$target"
  echo "Linked $skill -> $checkout/skills/$skill"
done

These commands are safe to run twice. An existing destination is reused only when it is a git checkout whose origin is this repository and it still holds the CLI, public/ and skills/publish-html-page; it is never pulled or replaced. An unrelated repository, an empty directory or an incomplete checkout stops with an error and is left untouched. Anything already at a skill destination — a skill, an empty directory, or a dangling symlink — is skipped and reported, never overwritten. The destination ~/.claude/skills/ is Claude Code's user skills directory; other agents use their own equivalent, and your agent can tell you where it loads skills from.

Finding the checkout from an installed skill

A symlinked skill points back into the checkout, so the checkout can be resolved from it and checked. A copied skill contains no scripts/ or public/: nothing is inferred from its location, and the retained checkout must be given explicitly in HTML_PUBLISHER_CHECKOUT. If neither produces a valid checkout, stop and ask; do not guess.

set -e
install_dir="$HOME/.claude/skills/publish-html-page"
resolved="$(readlink -f "$install_dir" 2>/dev/null || true)"
candidate=""
case "$resolved" in
  */skills/publish-html-page) candidate="${resolved%/skills/publish-html-page}" ;;
esac
valid_checkout() {
  [ -n "$1" ] && [ -f "$1/scripts/publish-html.mjs" ] && [ -d "$1/public" ] && [ -d "$1/skills/publish-html-page" ]
}
CHECKOUT=""
if valid_checkout "$candidate"; then CHECKOUT="$candidate"; fi
if [ -z "$CHECKOUT" ] && valid_checkout "${HTML_PUBLISHER_CHECKOUT:-}"; then CHECKOUT="$HTML_PUBLISHER_CHECKOUT"; fi
if [ -z "$CHECKOUT" ]; then
  echo "Cannot determine the html-artifact-publisher checkout." >&2
  echo "Install the skill as a symlink to the retained checkout, or set HTML_PUBLISHER_CHECKOUT to it." >&2
  echo "A copied skill does not contain scripts/ or public/ and cannot infer the checkout." >&2
  exit 1
fi
echo "$CHECKOUT"

Then invoke the CLI by absolute path (or cd "$CHECKOUT" first) and pass absolute artifact paths: node "$CHECKOUT/scripts/publish-html.mjs" /absolute/path/page.html. Keeping the checkout is necessary but not sufficient: the command has to name it.

Connect this instance

Publishing needs two environment variables:

export HTML_PUBLISHER_URL="https://this-instance.example"
export HTML_PUBLISHER_TOKEN="replace-with-your-personal-credential"

Create a named credential on API credentials, then load the secret from your environment or secret manager. Never put it in a URL, page content, browser storage or agent output.

What the agent gets

publish-html-page
Publishes a self-contained page, returns the read link, and updates the same page instead of creating duplicates.
artifact-design
Page contract: light and dark themes, no network access, phone widths.
artifact-runtime
window.artifact for pages that save state, edit themselves or keep a history.
artifact-diagrams, pikchr
When a diagram earns its place, and how to draw it.
artifact-dataviz
Charts that work in both themes.
self-host-publisher
Optional. Only for running a separate copy of this publisher on another Cloudflare account.
